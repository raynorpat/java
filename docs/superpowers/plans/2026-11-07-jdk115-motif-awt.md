# Phase 6: Linux Motif AWT implementation plan

> Use superpowers:executing-plans to implement and verify each task. The owner
> authorized this phase after completing and merging Phase 5.

**Goal:** Run the unchanged JDK 1.1.5 AWT and applet demos on Linux using a
reconstructed X11/Motif library informed by the supplied Solaris JDK 1.1.8/16.

**Architecture:** Keep the 1.1.5 VM and class archive as the baseline. Audit the
Solaris peer classes before selecting a separate compatible peer archive; retain
per-entry binary provenance for the native library. Adapt Solaris host services
to the existing Linux HPI and X11/Motif, with explicit compatibility boundaries.

**Tech stack:** 32-bit C/C++, original legacy native stack ABI, CMake/CTest,
Python inventory tooling, X11/Motif and Xvfb.

**Spec:** ../specs/2026-11-06-jdk115-reconstruction-design.md (Phase 6), and
2026-11-06-solaris118-inventory.md. Baseline master: 9beb8ab.

## Constraints and review focus

Preserve both original classes.zip archives and all source notices. No vendor
native library copies or placeholder exports in the reconstructed image. Linux
success does not establish Solaris runtime compatibility. Windows and console
Linux regressions remain green. The full Solaris runtime follows X11 AWT later.

Review the five main risks explicitly: inherited member/layout mismatches,
Java/native peer lifetime, lock ordering during X callbacks, pixel/font resource
ownership, and asynchronous focus/input/disposal. The tests below own those risks.

## Task 1: reproducible class and native-entry audit

Files: tools/awt118-audit.py, tools/solaris118-awt-native-entries.txt,
tests/awt118/audit-test.py, tests/awt118/compatibility.md.

Interfaces: parse_class(bytes) returns names, hierarchy, ordered field/method
descriptors, native declarations and constant-pool references; audit(base, solaris)
returns archive hashes, Motif classes and unresolved class/member references in
the proposed 1.1.5-plus-Motif overlay. This is a structural preflight, not proof
of native layout or runtime compatibility.

- [x] Capture matching release/debug native entry names with IDA; retain hashes.
- [x] Write failing tests using the real MButtonPeer native descriptors, inherited
  Object methods, and deliberately absent members; verify the missing tool fails.
- [x] Implement class-file 45.3 parsing and descriptor/hierarchy reference checks.
  Report absent supporting classes and unresolved members without replacing any
  baseline class. Do not silently infer runtime compatibility from a clean report.
- [x] Run tests and both-archive audit; cross-check native declarations with javap
  and IDA entry names. Record exact blockers and select the next Java-peer step.
- [x] Commit the audit and evidence.

## Task 2: compatible Java peer boundary

Files: cmake/motif118.cmake, tests/awt118/PeerLink115.java, and a separate generated
peer archive in the build tree; any necessary reconstructed Java peers live under
src/unix/sun/awt/motif. Consume Task 1's exact descriptors and unresolved list.

- [x] Test class loading, inherited field access and interface signatures against
  1.1.5; observe failures before corrections. Cover missing and inherited members.
  Extend audit tests to assert the baseline archive hash and explicit inherited
  field/interface resolution (nonblocking follow-ups from the Task 1 review).
- [x] Resolve each audit blocker through a documented peer/support-class choice
  or minimal Java reconstruction, without replacing java.* baseline classes.
- [x] Generate native headers/stubs from the selected classes; verify bindings
  against the entry inventory and commit the compatibility boundary.

## Task 3: toolkit and first live window

Files: src/unix/sun/awt/awt_Toolkit118.c, awt_Component118.c, awt_Frame118.c,
awt_Button118.c; tests/awt118/Window115.java and run118.cmake.

## Task 4: remaining widgets, input and window behavior

Input115.java, Menus115.java, Dialog115.java, Clipboard115.java.

- [ ] Recover and implement native groups from the audited bindings, one group

## Task 5: images, graphics, fonts and printing

Files: corresponding awt_Image118/Graphics118/Font118/Print118 units and
tests/awt118/Raster115.java, Fonts115.java, Print115.java.

- [ ] Recover image delivery, pixel formats, clipping/scaling, font conversion
  and print behavior. Test exact raster results and repeated resource retirement.
- [ ] Verify incremental/aborted image delivery and callbacks during disposal;
  retain the established shareable 1.1.5 codec contracts and commit verified groups.

## Task 6: installed image and demo completion

- [ ] Run all unchanged applet and awt-1.1 demos through an installed Linux image,
  with Xvfb interaction and visual checks. Verify no vendor native copies.
- [ ] Run full Windows/Linux Debug/Release suites and exact native binding audits.
- [ ] Obtain a fresh branch review and close every implementation/demo gate before
  claiming Phase 6 complete. Full Solaris runtime reconstruction remains separate.

Status: Tasks 1 and 2 complete; Tasks 3 and 4 are active. The separate 76-class
archive changes only InputContext's toolkit factory owner. All 199 generated
bindings match the inventory, with 66 native entries implemented so far.
Live Xvfb checks cover toolkit startup, basic fonts/painting, frame/button
lifetime, mouse/key/focus dispatch, labels, checkboxes and scrolled lists.
Evidence and remaining limitations are in tests/awt118/bootstrap-evidence.md.
Remaining widgets, full input/window behavior, graphics/images/printing,
installed demos and the final regression/review gates keep Phase 6 incomplete.
