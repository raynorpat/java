# JDK 1.1.5 VM Core (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the tree's JDK 1.0.2 VM into a faithful reconstruction of Sun's JDK 1.1.5 `javai` that runs Sun's 1.1.5 `classes.zip`, including `javac`, on Windows and Linux.

**Architecture:** Sun's 1.1.5 headers (shipped source) are adopted first and define every structure and HPI function. Each VM subsystem is then reconstructed by decompiling `javai.dll`/`javai_g.dll` (Win32) with Rhapsody DR2 `libjava.A.dylib` (1.1.5, 538 symbols) for names, starting from the 1.0.2 code where Sun kept it. Every behaviour is pinned by a Java test whose expected output is captured from Sun's own 1.1.5 VM.

**Tech Stack:** C89; MSVC (Win32) and GCC `-m32` (Linux); CMake 3.0...3.10 + CTest; IDA (databases already exist for the Rhapsody libraries); Sun JDK 1.1.5 `javac` for test classes.

**Spec:** `docs/superpowers/specs/2026-11-06-jdk115-reconstruction-design.md`. This plan covers spec step 1 (VM core) plus the vendor/layout groundwork. Steps 2–7 (support libraries, Unix cthreads, `winawt`, `jdb`/`JdbcOdbc`, Motif, Rhapsody) each get their own plan after this one lands.

## Global Constraints

- C89 for all C code; must compile with MSVC 32-bit and `gcc -m32 -std=c89 -pedantic` without C89 errors.
- 32-bit only. CMake `3.0...3.10`.
- Faithful to Sun's 1.1.5: file names, function names, structures and constants follow the binaries and Sun's headers. Reconstructed code wins over our existing code except bug fixes.
- Every reconstructed `.c` file starts with `/* Reconstructed from JDK 1.1.5 javai.dll (Win32) and Rhapsody DR2 libjava.A.dylib. */`; any kept deviation from Sun (bug fixes, pthreads) carries a `/* deviation: <why> */` comment; anything genuinely invented carries `/* reconstructed: <what was guessed> */`.
- Kept deviations: the GC fixes in `gc.c` (zeroing new objects, handle-space rounding, no synchronous finalization in allocation, scanning the enumerated thread, register scanning) and the POSIX pthreads layer behind `#ifdef USE_PTHREADS` (Linux default).
- Only source in git: Sun/Apple binaries and data live in git-ignored `vendor/`. Sun's shipped headers and `demo/jre/*.c` are source and are committed.
- Windows and Linux both build and pass CTest at the end of every task (Linux via the 32-bit setup: `CC="gcc -m32"`, see Task 1).
- Commits: short, subsystem-prefixed (`build:`, `runtime:`, `md:`, `tests:`, `javah:`), no metadata.

## Review Focus

1. **Classpath forms** — `-classpath` with directories, zips, missing entries and empty elements; `CLASSPATH` env; 1.1's default (`.` + `<java.home>/lib/classes.zip`). Expect Sun's behaviour, never a crash. Test: `ClassPathForms` in Task 4.
2. **Non-ASCII text** — strings with `\u00e9`, `\u4e2d` and surrogate-free BMP chars through `String`, `System.out`, `getBytes`, and file names. Expect Sun's bytes. Test: `Unicode` in Task 4.
3. **Exceptions in static initializers** — 1.1's `ExceptionInInitializerError` and `NoClassDefFoundError` on second use. Test: `ClinitFail` in Task 8.
4. **`Thread.interrupt()`** during `sleep`, `wait` and `join` (new behaviour in 1.1) must throw `InterruptedException` and clear the flag. Test: `Interrupt` in Task 9.
5. **Inner classes and old classes** — classes with `InnerClasses` attributes and classes compiled by 1.0.2 `javac` both load and verify. Test: `InnerAndOld` in Task 8.

`javap/` and `classsrc/` are deleted (1.1.5 `javap` is a Java tool; 1.0.2 classes are replaced).
