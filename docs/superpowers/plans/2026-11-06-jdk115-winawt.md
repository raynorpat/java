# JDK 1.1.5 Windows AWT (Phase 4) Implementation Plan

> **For agentic workers:** The coordinator executes controls/integration inline.
> Remaining Task4 uses superpowers:subagent-driven-development with separate
> file/build ownership and a task review before integration (see ledger).

**Goal:** Reconstruct winawt so the unchanged Windows applet, awt-1.1 and GUI
i18n demos run on the reconstructed JDK.

**Architecture:** Recover the 1.1.5 native interfaces from winawt.dll and its
debug companion, using the unchanged peer classes for Java layouts. Follow
the binary's src/win32/sun/windows C++ organization. The retained 1.0.2 MFC
implementation is comparison material, not a compatible library to enable.

**Tech Stack:** MSVC Win32 C++, existing C89 VM/HPI, CMake/CTest, native Win32/GDI.

**Spec:** ../specs/2026-11-06-jdk115-reconstruction-design.md

## Constraints

- 32-bit only; C++ is restricted to winawt. Linux must remain green.
- Do not modify vendor classes.zip or demos; source only in git.
- Preserve notices on reused source and mark adaptations explicitly.
- Reconstruct behavior from binaries; no placeholder peers advertised as complete.
- Branch build/jdk115-winawt starts at Phase3 completion 11acae4. Keep the
  existing checkout/vendor/build paths; no master merge is implied by starting
  this phase.

## Review focus

- Dispose racing queued events must never dereference a freed peer.
- Toolkit startup/shutdown and cross-thread calls must not deadlock VM monitors.
- Java peer/image references must survive GC during native callbacks.
- Invalid image extents, clip bounds and array lengths must not access outside buffers.
- Font encoding, keyboard events and focus transitions must work beyond ASCII.
